Complexity analysis

See how work and memory grow. Count the loop, draw the calls, track what stays alive, then choose a bound you can justify.

Start with basic Python variables, lists, loops, and functions. This lesson builds from one scan to recurrence trees, amortized analysis, independent inputs, and hidden copying costs.

First pass: growth, bounds, loops, and memory. Then go deeper: recursion trees, the Master Theorem, and amortized analysis. Use the eight analysis problems and the recursive-sum task to check your reasoning.

Count growth, then measure seconds

The same code runs at different speeds on an older phone and a modern workstation. CPU and memory architecture, the compiler or interpreter, and background work all influence elapsed time. To compare algorithms, first ask: how does the workload grow when the input grows?

Let N be the input size, such as the length of a list. Choose a counted operation: a comparison, a cell visit, or an emitted pair. Then ask what happens when N doubles, triples, or reaches one million. Asymptotic analysis describes the growth of that count for sufficiently large inputs. A benchmark later answers how the implementation performs on the inputs and machine you actually use.

Our cost model. Unless stated otherwise, examples count fixed-size arithmetic, indexing, and equality as constant-time operations. For printing examples, count each emission as one event; formatting, output length, and actual I/O can add work. Python integers can grow, strings can take multiple character comparisons, and allocating objects is not free. We state these limits rather than treating source lines as machine instructions. Numeric inputs are nonnegative integers unless a different precondition is given. For a numeric parameter n, N denotes its value here; a binary encoding of that value has only about log₂ N bits.

Bounds and cases are separate questions

First choose the function you want to analyze: the best, worst, or expected cost for inputs of size N. Then describe that function with a bound. O is an upper bound, Ω is a lower bound, and Θ is a matching upper and lower bound. They do not mean worst case, best case, and “both cases agree.”

One algorithm, different cases

def contains(values, target):
    for value in values:
        if value == target:
            return True
    return False

print(contains([4, 8, 12], 8))
print(contains([4, 8, 12], 9))

Output

True
False

The first position may match after one comparison: Θ(1) best-case time. An absent target needs N comparisons: Θ(N) worst-case time. Both are tight bounds on different cost functions. Expected cost needs assumptions about how inputs or targets are distributed. This scan uses O(1) auxiliary space.

In conversation, people often ask for “Big-O” and expect the tightest useful upper bound. A loop that always visits N items is O(N), and the stronger description is Θ(N). Calling it O(N²) is a valid loose upper bound, but hides useful information.

Simplify the count without losing the model

Suppose your operation count is f(N) = 3N² + 5N + 12. For large N, constant multipliers do not change the growth class, and the fastest-growing term dominates the sum.

RuleExamples
Drop constant factorsO(2N) = O(N); O(500) = O(1); O(N/2) = O(N).
Drop lower-order termsO(N² + N) = O(N²); O(N log N + N³ + 45) = O(N³).

Recognize the growth spectrum

These are common workload models. Their eventual ordering is constant, logarithmic, linear, linearithmic, polynomial, exponential, then factorial. Small-input curves can cross; an upper bound alone does not promise a faster implementation.

GrowthNameA useful example
O(1)ConstantDirect array indexing; expected hash-table lookup under normal hashing assumptions.
O(log N)LogarithmicBinary search on a sorted random-access array.
O(N)LinearVisit every input item once.
O(N log N)LinearithmicMerge sort; expected quicksort with appropriate pivot assumptions. Quicksort can take Θ(N²) in the worst case.
O(N²)QuadraticAll ordered pairs of N items.

Doubling the counter creates logarithmic growth

def logarithmic_loop(n):
    i = 1
    while i < n:
        print(i)
        i = i * 2              # Counter doubles every step

logarithmic_loop(8)

Output

1
2
4

For N = 8, the printed values are 1, 2, 4: three iterations. After the third update, i becomes 8, so i < n is false. Solving 2ˣ ≥ N gives ⌈log₂ N⌉ iterations for N ≥ 1. The equality 2ˣ = N is exact at powers of two.

Multiplying by a fixed factor greater than one, or dividing a positive counter until a stopping boundary is reached, commonly produces logarithmic iteration counts. Check that each update actually makes progress: repeatedly flooring 1/2 without a proper guard can break a poorly designed loop.

A branch needs a stated case

def conditional_branch(n, condition):
    if condition:
        # Branch A: Linear time
        for i in range(n):
            print(i)           # O(N)
    else:
        # Branch B: Quadratic time
        for i in range(n):
            for j in range(n):
                print(i, j)    # O(N^2)

conditional_branch(2, True)
conditional_branch(2, False)

The true branch is Θ(N); the false branch is Θ(N²). Therefore the worst-case function is Θ(N²). Big-O did not choose that case for us. If the quadratic branch occurs with a fixed probability of 1%, its N² contribution still dominates the expected cost for large N. If its probability changes with N, include that probability in the analysis.

def adjacent_comparisons(values):

Answer and reasoning

No. The inner loop performs at most two iterations for each i. For N = 8, it emits 13 comparisons; for N ≥ 2, the count is 2N − 3, so time is Θ(N).

Track the memory that is alive at once

Time adds work across execution. Space measures the peak live storage, not how many allocations have ever happened. State which categories you include:

InputThe data provided to the function.
Working memoryTemporary structures, local state, and active call frames.
Returned outputThe result retained by the caller.

Many analyses report working auxiliary space and output space separately; others include output in auxiliary space. Name the convention instead of assuming one. If an input array occupies Θ(N) storage and a scan keeps only a few fixed-size variables, its auxiliary working space is O(1), while total space including input is Θ(N).

A fixed number of scalar slots

def constant_space(n):
    result = 0             # O(1) space
    for i in range(n):     # i is O(1) space
        result += i
    return result

print(constant_space(5))

Output

10

The loop updates a constant number of variable slots, so it uses O(1) working words under our model. Python integers are immutable and may allocate replacement objects; the old temporary need not remain live. Exact integer bit storage can grow as values grow, so “O(1) words” is not a claim that arbitrarily large integers use a fixed number of bytes.

A collection proportional to N

def linear_space(n):
    visited_set = set()    # Space scales with N
    for i in range(n):
        visited_set.add(i) 
    return visited_set

print(sorted(linear_space(4)))

Output

[0, 1, 2, 3]

The returned set stores N items: Θ(N) result storage. Counting that set as allocated extra memory also gives Θ(N) space. Hash insertions take expected amortized O(1) time under normal assumptions. The sorted call here only makes the displayed set output deterministic; it is not part of linear_space.

A grid proportional to N²

def quadratic_space(n):
    # Creates an N x N matrix initialized to zeros
    matrix = [[0] * n for _ in range(n)]
    return matrix

print(quadratic_space(2))

Output

[[0, 0], [0, 0]]

There are N separately created row lists and N² cell references, so the result occupies Θ(N²) storage. Zero is shared as an immutable value; the cell slots still exist. This construction avoids the shared-row trap in [[0] * n] * n.

Count calls for time, active frames for space

A recursive function calls itself on a smaller problem. It needs a base case that returns directly and a progress rule that reaches it. Each unfinished call keeps a stack frame with local state and a place to resume.

def recursive_countdown(n):
    if n <= 0:
        return
    recursive_countdown(n - 1)

print(recursive_countdown(3))

Output

None

Countdown creates calls for 3, 2, 1, and 0: four simultaneous frames at maximum depth. In general, nonnegative N creates N + 1 frames. It has Θ(N + 1) time and Θ(N + 1) stack space; an iterative countdown uses O(1) auxiliary space. An iterative loop alone does not guarantee constant stack use if its body invokes deeper helpers.

Watch unfinished additions return

def triangle(n):
    if n == 0:
        return 0
    return n + triangle(n - 1)

print(triangle(3))

Output

6
Call downwardtriangle(3) waits for 3 + triangle(2), then 2 + triangle(1).
Reach zerotriangle(1) waits for 1 + triangle(0). The base case returns 0.
Return upwardReturn 1, then 3, then 6 as the pending additions finish.

T(N) = T(N − 1) + Θ(1) ⇒ Θ(N) time; Θ(N) active stack frames for N ≥ 1.

For triangle, require a nonnegative integer: a negative value moves farther from zero. Python has a recursion limit and does not eliminate these frames. Keep tracing examples small; a loop can sum the same range with O(1) working space.

Naive Fibonacci branches into repeated subproblems. Its call count grows exponentially, while its maximum active path grows linearly. Memoization saves solved states and reduces the number of distinct state computations to O(N). Follow the memoization lab after the core recursion model makes sense.

Use a recursion tree, then a theorem

A recurrence expresses an input’s cost in terms of smaller inputs. Merge sort creates two half-size problems and spends linear work combining their results. For powers of two with constant-cost base cases:

T(N) = 2T(N/2) + Θ(N).

There are log₂ N splitting levels before size one. Each internal level performs Θ(N) total merge work, and the leaves add Θ(N) base work. Hence merge sort takes Θ(N log N) time for N ≥ 2. Its recursion stack uses Θ(log N) frames, but an ordinary array merge sort also needs Θ(N) temporary storage, making its total auxiliary space Θ(N). Track buffers and live slices as well as call frames.

The Master Theorem has conditions

The standard template is T(N) = aT(N/b) + f(N), with constants a ≥ 1 and b > 1, nonnegative combine work f(N), and a constant-cost base case. Define p = logba. Compare f(N) with Np. These three common cases require more than a vague comparison of “root versus leaves.”

Case and conditionTight resultExample
f(N) = O(Np − ε) for some ε > 0Θ(Np)8T(N/2) + Θ(N²) ⇒ Θ(N³): recursive classical matrix multiplication.
f(N) = Θ(Np)Θ(Np log N)2T(N/2) + Θ(N) ⇒ Θ(N log N): merge sort.
f(N) = Ω(Np + ε), plus a·f(N/b) ≤ q·f(N) eventually for some q < 1Θ(f(N))2T(N/2) + Θ(N²) ⇒ Θ(N²): a hypothetical quadratic combine step.

The ε condition means a polynomial gap; case three also needs the regularity inequality shown above. A balanced quicksort recurrence fits the equal-work case, not the root-dominant case. General quicksort partitions can be unequal, and Fibonacci’s N − 1 and N − 2 calls do not fit this template. Logarithmic factors can require an extended theorem. When a recurrence does not fit, use a tree, expansion, or a separate proof. See the NIST template and NYU theorem conditions.

Spread occasional resizing over the whole sequence

One append can be expensive while a long sequence remains cheap on average per operation. Amortized analysis bounds the total cost of an operation sequence; it does not assume random inputs or deny the expensive individual operation.

Use an educational dynamic array that begins with capacity 1 and doubles when full. Count one unit for each new element write and one for each reference copied during a resize. Capacity allocation overhead is outside this unit model; including proportional allocation work preserves the linear sequence bound.

Copied references: 1 + 2 + 4 + … < 2N. Writes: N. Total < 3N for N ≥ 1.

There can be several resizes in the sequence, not just one. Each append is Θ(1) amortized under geometric growth, while a single resizing append can take Θ(N). Python lists use over-allocation rather than this exact doubling schedule; the familiar append guarantee is amortized O(1). This is separate from average-case analysis over an input distribution.

Keep independent dimensions independent

If one list has A items and another has B, no relationship between A and B is implied. Give each its own variable before simplifying.

Every cross-input pair

def match_elements(list_a, list_b):
    for item_a in list_a:      # Runs A times
        for item_b in list_b:  # Runs B times for every item_a
            print(item_a, item_b)

match_elements([1, 2], [7, 8, 9])

Output

1 8
1 9
2 7

2 9

A groups × B emissions ⇒ A·B emissions; including loop overhead, O(1 + A + A·B) time.

For positive A and B the usual shorthand is Θ(A·B). If B is empty, the outer loop can still run A times; the fuller expression handles that boundary. Rectangular matrices use R rows and C columns, so a complete cell scan is O(R·C) for nonempty rows. With adjacency lists, BFS and DFS commonly use O(V + E), where V counts vertices and E counts edges examined.

Unpack the work hidden inside a single call

A built-in method can contain an entire loop. These bounds describe Python-style flat lists and strings with constant-cost element comparisons; they are not universal guarantees for similarly named JavaScript operations.

Growing an immutable string can repeatedly copy its prefix

In a flat-copying model, constructing N one-character chunks copies prefixes of lengths 1, 2, …, N, for Θ(N²) total character work. def build_word_joined(char_list):

Joining N chunks of total length L takes O(N + L) work and Θ(L) result storage. For N single characters, L = N. This avoids relying on repeated-concatenation optimization. The Python FAQ recommends collecting chunks and joining them.

In the recursive reversal problem below, every waiting frame retains its own string. Counting the frames alone misses those live copied characters.

Use the bound to guide measurement

Asymptotic analysis lets N grow without bound. Real workloads are finite. A quadratic method with a small constant can beat a method with better growth and a large setup cost on small inputs; there is no universal crossover such as “N < 50.” Measure the implementations on representative data.

Two linear traversals can have different real costs. A primitive contiguous array benefits from cache locality; a linked structure follows scattered pointers. Python lists are contiguous arrays of object references, while the referenced objects can live elsewhere. Language and representation matter. The ADT-to-CPU foundation note connects the abstract cost model to runtime, allocator, memory, and hardware behavior.

  1. Define every input-size variable and the input constraints.
  2. Choose a case and a cost model, then count actual repetitions.
  3. Include copying, comparison, hashing, and allocation work hidden in calls.
  4. Write a sum or recurrence before simplifying it.
  5. Report peak working space, recursion depth, and output storage separately.
  6. Check small, empty, and adversarial cases; then benchmark the actual implementation.

Pair the cost claim with a correctness invariant

An invariant is a fact preserved at a chosen point during an algorithm. Before each iteration of this loop, total is the sum of the values already visited:

total = 0
for value in [2, 5, 1]:
    total += value
    print(total)

Output

2
7
8

It starts at zero for the empty prefix, remains true when the next value is added, and gives the whole sum at termination. The loop is linear, but the invariant explains why its result is correct. Carry both questions into the labs: “How much work grows?” and “Why is the next move safe?”

1. All unordered pairs

This is a dependent pair enumeration, not a sliding-window algorithm. For three values, predict the printed pairs, then derive the number of emissions and working space.

def find_all_pairs(arr):
    n = len(arr)
    for i in range(n):
        for j in range(i + 1, n):
            print(arr[i], arr[j])

find_all_pairs([2, 5, 9])

Output

2 5
2 9
5 9
Worked solution for problem 1

For N items, the inner loop emits (N − 1) + … + 1 = N(N − 1)/2 pairs, so time is Θ(N²) for large N. Working space is O(1) words, excluding streamed output. An empty or one-item list emits nothing.

2. Intersection with repeated matches

Let A and B be the two list lengths. Preserve the function’s duplicate behavior. Analyze working space and returned output separately, including when B repeats one matching value many times.

def get_intersection(list_a, list_b):
    seen = set(list_a)
    intersection = []
    
    for item in list_b:
        if item in seen:
            intersection.append(item)
            
    return intersection

print(get_intersection([1], [1, 1, 1, 1, 1]))

Output

[1, 1, 1, 1, 1]
Worked solution for problem 2

Expected time is O(A + B) with suitable hash behavior. The set stores Uₐ distinct items, at most A: O(Uₐ) working space excluding output. The result stores K matching occurrences, at most B, so allocated extra space including the result is O(Uₐ + K), at most O(A + B). K is not bounded by min(A,B): this example has A = 1 and K = 5. The routine preserves matching occurrences from B rather than returning a mathematical set intersection.

3. A shrinking loop with a full inner scan

Analyze the original input N, even though the local variable n changes. Explain why multiplying N by log N overcounts the work.

def count_operations(n):
    count = 0
    while n > 0:
        for i in range(n):
            count += 1
        n = n // 2
    return count

print(count_operations(8))

Output

15
Worked solution for problem 3

The work is N + ⌊N/2⌋ + ⌊N/4⌋ + … . For N ≥ 1 it lies between N and 2N, so time is Θ(N), not Θ(N log N). For N = 8, the sum is 8 + 4 + 2 + 1 = 15. The outer-loop overhead is O(log N), dominated by the scan work. Working space is O(1) words; N = 0 returns zero.

4. The recursive string slicer

Assume ordinary CPython strings with copied nontrivial suffix slices. Track both the active frames and every suffix still referenced by those frames.

def reverse_string(text):
    if len(text) <= 1:
        return text
    # text[1:] slices the string from index 1 to the end
    return reverse_string(text[1:]) + text[0]

print(reverse_string("banana"))

Output

ananab
Worked solution for problem 4

Time is Θ(N²) under the flat-copying model: suffix creation and concatenation repeatedly process decreasing string lengths. There are Θ(N) active frames, and their retained suffixes require Θ(N²) peak auxiliary character storage in CPython. Counting only frames would give the wrong total. The returned string itself is Θ(N). An empty or one-character input returns directly. An implementation with shared substring views would require a different storage analysis.

5. A branching Fibonacci tree

Require a nonnegative integer and use small inputs. Give an upper bound on the number of calls, then distinguish that from the maximum active depth.

def calculate_fibonacci(n):
    if n <= 1:
        return n
    
    # Notice there are TWO recursive calls per function
    return calculate_fibonacci(n - 1) + calculate_fibonacci(n - 2)

print(calculate_fibonacci(6))

Output

8
Worked solution for problem 5

O(2ᴺ) is a valid upper bound, but the branches are not a perfect full binary tree of equal depth. The tight call-growth bound is Θ(φᴺ), where φ = (1 + √5)/2. Maximum active depth is Θ(N), so stack space is O(N) under the fixed-size arithmetic model. Exact growing-integer costs require a bit-complexity model. Memoization changes the state-computation count to O(N).

6. Binary search boundaries

Require a sorted random-access array with constant-cost comparisons. Analyze the worst case and the immediate-hit case, and state the empty-array result.

def binary_search(arr, target):
    left = 0
    right = len(arr) - 1
    
    while left <= right:
        mid = (left + right) // 2
        
        if arr[mid] == target:
            return mid
        elif arr[mid] < target:
            left = mid + 1
        else:
            right = mid - 1
            
    return -1

print(binary_search([2, 4, 6, 8, 10], 8))
print(binary_search([], 8))

Output

3
-1
Worked solution for problem 6

Worst-case time is Θ(log(N + 1)), conventionally O(log N) for N ≥ 2. A first middle-element hit is Θ(1). Each iteration reduces the candidate interval by roughly half; it is not always an exact half because endpoints are integers. Working space is O(1) words. The empty array returns −1.

7. A rectangular or ragged matrix

First assume R nonempty rows of C values. Then ask what changes if row lengths differ, including empty rows.

def search_matrix(matrix, target):
    # matrix is a list of lists (a 2D grid)
    for row in matrix:
        for val in row:
            if val == target:
                return True
    return False

print(search_matrix([[1, 2, 3], [4, 5, 6]], 5))
print(search_matrix([[], [7]], 8))

Output

True
False
Worked solution for problem 7

For a rectangular matrix with positive R and C, the worst case visits R·C cells: Θ(R·C) time, with O(1) working space. An early hit may take Θ(1). For ragged rows, include row-iteration overhead: O(1 + R + Σ len(row)); R empty rows still take Θ(R) work. The value-search code does not assume sorted rows or columns.

8. A character counter with a bounded alphabet

Analyze two passes over N characters. State the alphabet assumption rather than silently treating all dictionaries as constant space.

def first_unique_character(string):
    char_counts = {}
    
    # First pass: count frequencies
    for char in string:
        if char in char_counts:
            char_counts[char] += 1
        else:
            char_counts[char] = 1
            
    # Second pass: find the first unique
    for i in range(len(string)):
        if char_counts[string[i]] == 1:
            return i
            
    return -1

print(first_unique_character("swiss"))
print(first_unique_character("aabb"))

Output

1
-1
Worked solution for problem 8

Expected time is Θ(N) under normal hash assumptions. If the alphabet has Σ possible symbols, the dictionary needs O(min(N,Σ)) entries. Guaranteed lowercase English input limits it to 26 keys; ASCII has 128 code points, not 256. A fixed alphabet gives O(1) working words in N under the stated word model. If the model allows a growing symbol set with U distinct symbols, report O(U). Python’s Unicode alphabet is finite, but Σ can still be a useful explicit parameter. The counter integers themselves have bit-storage costs if arbitrary sizes are included.

9. Build a recursive sum from an index

For [2, 5, 1, 4], write a recursive suffix sum and an iterative version. Require an integer index from zero through the list length. Name the base case, progress rule, and the time/space difference.

Worked solution for the recursive sum
def sum_from(values, index):
    if index == len(values):
        return 0
    return values[index] + sum_from(values, index + 1)

def sum_iterative(values, index):
    total = 0
    for i in range(index, len(values)):
        total += values[i]
    return total

values = [2, 5, 1, 4]
print(sum_from(values, 0), sum_from(values, 4))
print(sum_iterative(values, 0))

Output

12 0
12

The index advances to len(values), where the empty suffix returns zero. With r remaining values, both versions use Θ(r + 1) time. Recursion uses Θ(r + 1) stack space; iteration uses O(1) working space.
